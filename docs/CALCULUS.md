# Анализ рядов и разделение интегрирования — 0.8.2

## Первообразная и определённый интеграл

`antiderivative(expr,x)` находит одну первообразную по вещественной координате x.
Произвольная константа не добавляется. `integrate(expr,x,a,b)` вычисляет
определённый интеграл от a до b. Координата должна быть объявленным символом
типа `Real`, границы — вещественными скалярами, независимыми от неё.

```text
x:Real
antiderivative(x^2,x)                    // 1/3*x^3
integrate(x^2,x,0,1)                     // 1/3
integrate(x^2,x,1,0)                     // -1/3
integrate(sqrt(x),x,0,4)                 // 16/3

F=antiderivative(x)
F(x^2)                                 // 1/3*x^3
I=integrate(x,0,1)
x^2 |> I                               // 1/3
```

Операторы можно хранить, передавать и использовать в pipeline. Для функции
одного аргумента `integrate((t:Real)=>t^2,x,0,1)` возвращает скаляр 1/3;
`antiderivative` возвращает функцию. Встроенные операции доступны также через
`std.analysis` и `std.analysis.calculus`. В Python это методы `Calculus` и
экспортируемые функции `antiderivative(expr,var)` и `integrate(expr,var,a,b)`;
выражение, координата и границы передаются как объекты `Term`.

В исходниках до 0.8.2 `integrate(expr,x)` обозначал первообразную. Его нужно
заменить на `antiderivative(expr,x)`; сохранённый оператор `integrate(x)` —
на `antiderivative(x)`. Старое число аргументов теперь даёт диагностику с
подсказкой миграции. Эта смена касается и Python API.

## Поддерживаемые определённые интегралы

Вычисление точное: проверка регулярности подынтегрального выражения на всём
замкнутом интервале, построение первообразной и разность её значений на концах.
Поддерживаются классы существующего алгоритма первообразных: многочлены,
линейные комбинации, постоянные множители, выбранные элементарные функции и
числовые степени аффинного аргумента. Это не общий символьный интегратор и
не численная квадратура. Границы можно менять местами; нулевая длина даёт
ноль только после проверки определённости выражения.

Для рациональных числовых границ применяется консервативная интервальная
проверка операций. Знаменатель должен быть ненулевым на всём интервале,
аргумент log — строго положительным, sqrt — неотрицательным. Например,
`integrate(1/x,x,1,2)` даёт `log(2)`, а интервал от −1 до 1 отклоняется.
Проверяются внутренние особенности и концы; множитель 0 не скрывает полюс.
Текущая проверка tan ограничена аргументами внутри [−1,1] радиан, а поиск
первообразной дополнительно ограничивает поддерживаемые случаи.

Символические границы работают для выражений с установленной областью
определения, например многочленов:

```text
x:Real
a:Real
b:Real
integrate(x^2,x,a,b) |> substitute(a=0,b=3) |> simplify   // 9
```

Неизвестная область определения отклоняется, даже если интеграл в принципе
существует. Например, произвольные a,b недостаточны для `integrate(1/x,x,a,b)`.
Несобственные интегралы, бесконечные границы, главное значение и разбиение
на куски пока не поддержаны. Предположения контекста ещё не выбирают формулы
анализа. Область исходного выражения сохраняет правила языка: в частности,
`x^0` не определено при x=0; для постоянного члена ряда используйте 1.

## Усечённые ряды Тейлора

`series(expr,x=a,order=n)` хранит коэффициенты степеней от 0 до n−1 и остаток
`O((x-a)^n)`. Операции над таким объектом используют его собственную координату.

| Операция | Результат и граница |
| --- | --- |
| `derivative(S,x,order=k)` | Почленная производная, порядок остатка n−k; k≤n |
| `antiderivative(S,x)` | Почленная первообразная, остаток порядка n+1; постоянный коэффициент 0 |
| `limit(S,x -> a)` | Постоянный коэффициент в центре; нужен хотя бы один известный коэффициент |
| `series(S,x=a,order=m)` | Усечение до m≤n в том же центре |
| `polynomial(S)` | Явное отбрасывание остатка, обычное скалярное выражение |

Производная и первообразная сохраняют `Series<Real>` в типизированных
функциях и Typed IR. Производная порядка n оставляет `O(1)`; такой остаток
не определяет предел. Предел в другой точке, повышение порядка и смена
центра требуют исходного выражения.

```text
x:Real
S=series(exp(x),x=0,order=6)
derivative(S,x)                          // ... + O(x^5)
antiderivative(S,x)                      // ... + O(x^7)
limit(S,x -> 0)                         // 1
integrate(polynomial(S),x,0,1)           // 1237/720
```

Последнее число — интеграл приближающего многочлена, а не точный интеграл
исходной экспоненты. `integrate(S,x,0,1)` отклоняется: неизвестный остаток
не позволяет получить точный скаляр. Допускается тривиальный нулевой интервал
в центре ряда с известным постоянным коэффициентом. Оценка ошибки приближения
автоматически не строится.

## Символические конечные суммы

Индексные суммы с ещё неизвестными границами поддерживают почленный анализ:

```text
x:Real
n:Nat
P=sum(1,n) {(index:Nat)=>x^index/factorial(index)}
dP=derivative(P,x)
FP=antiderivative(P,x)
AP=integrate(P,x,0,1)
substitute(dP,n=3)                      // x^2/2 + x + 1
substitute(FP,n=2)                      // x^2/2 + x^3/6
substitute(AP,n=2)                      // 2/3
```

Производная, первообразная, определённый интеграл или предел каждого слагаемого
сохраняются как отложенный запрос. После подстановки границ сначала подставляется
целый индекс, затем выполняется анализ слагаемого. Это сохраняет проверки типов,
областей определения и общий бюджет вычисления. Связанный индекс получает свежую
идентичность, чтобы не захватить одноимённую внешнюю координату анализа.

Границы суммы должны быть независимы от координаты анализа; слагаемое задаётся
явной функцией одного аргумента. Преобразование работает для самой `sum` и
требует существования поддерживаемой операции для каждого слагаемого. Общая
линейность для произвольного выражения с несколькими нераскрытыми свёртками,
анализ символического product и построение TaylorSeries из символической суммы
ещё не реализованы — сначала подставьте конечные границы. Бесконечные ряды,
проверки сходимости и перестановка бесконечной суммы с пределом не вводятся.

## Численное значение точного результата

Аналитические операции по умолчанию возвращают точное символьное значение. Если после
дифференцирования, интегрирования, подстановки или вычисления предела получено замкнутое
вещественное выражение, его можно явно приблизить через pipeline:

```text
integrate(exp(x), x, 0, 1) |> numeric(30)
// ≈1.71828182845904523536028747135

series(exp(x), x, 0, 8)
    |> substitute(x=1)
    |> numeric(25)
```

`numeric` не меняет семантику анализа и не заменяет остаточный член числом. Он применяется
только к уже полученному замкнутому выражению. Результат имеет отдельный узел
`ApproxNumber`, поэтому приближение нельзя спутать с точным десятичным литералом. Подробнее:
[NUMERIC.md](NUMERIC.md).

## IDE, сохранение и проверки

IDE подсвечивает и дополняет `antiderivative`, `integrate`, `factorial` и
итерационные операции. Preview показывает ∑/∏, факториал и интегралы с границами;
панель Types сохраняет сигнатуру шага и тип ряда до вычисления.

Начиная с `mathlang-ir` 4 сохраняются обе границы определённого интеграла.
Текущий формат 7 читает версии 1–6: старые операторы первообразной и идентичность встроенного
`integrate` переводятся в `antiderivative`. Версия 7 добавляет `ApproxNumber` для явных
результатов `numeric`; точные результаты анализа сериализуются как прежде. Имена
пользовательских экспортов при этом сохраняются. Старые программы должны обновить
исходники; старые читатели отклонят новый формат. Сохранение обычных функций и
блоков использует существующие узлы Function/FunctionCall.

Выполняемый пример: [series_calculus.math](../examples/series_calculus.math).
Проверки в [test_analysis_extensions.py](../tests/test_analysis_extensions.py)
сверяют факториалы и полиномиальные интегралы с независимыми формулами,
проверяют типы, связывание, полюса, остатки, лимиты, старый IR и MathText.
