# Численное вычисление — 0.9.2

MathLang по умолчанию остаётся **точным символьным языком**. Литерал `0.125`
хранится как рациональное число `1/8`, а `sqrt(2)`, `exp(1)` и `sin(1)` не
заменяются машинными `float` автоматически.

Версия 0.9.2 добавляет отдельное явное преобразование `numeric`, которое можно
использовать как обычную функцию или как цель pipeline.

```text
sqrt(2) |> numeric
// ≈1.4142135623730950488

sqrt(2) |> numeric(30)
// ≈1.41421356237309504880168872421

exp(1) |> numeric(30)
// ≈2.71828182845904523536028747135
```

## Синтаксис

```text
numeric(expression)
numeric(expression, digits)

expression |> numeric
expression |> numeric(digits)
```

`digits` — число значащих десятичных цифр. По умолчанию используется 20.
Текущая реализация принимает от 1 до 500 цифр.

Pipeline использует обычное правило языка:

```text
value |> f(a, b)
```

эквивалентно

```text
f(value, a, b)
```

поэтому

```text
sqrt(2) |> numeric(50)
```

разрешается как `numeric(sqrt(2), 50)`.

## Поддерживаемая область

Текущий backend вычисляет **замкнутые вещественные скалярные выражения** из:

- точных рациональных чисел;
- `+`, `-`, `*`, `/`;
- целых и вещественных степеней в вещественной области;
- `sqrt`;
- `exp`;
- `log`;
- `sin`;
- `cos`;
- `tan`;
- `abs`.

Пример после символьной подстановки:

```text
variable x : Real

sin(x) + sqrt(2)
    |> substitute(x=1)
    |> numeric(24)
// ≈2.25568454718099155545419
```

`numeric` можно применять к точному результату анализа:

```text
variable x : Real

integrate(exp(x), x, 0, 1)
    |> numeric(24)
// ≈1.71828182845904523536029
```

Сначала выполняется символьный calculus backend, затем полученная закрытая
формула численно вычисляется.

## Почему результат — не `Number`

В исходном языке десятичный литерал точен:

```text
0.1
```

означает рациональное `1/10`. Поэтому численное приближение нельзя безопасно
представлять тем же IR-узлом.

0.9.2 вводит отдельный терм `ApproxNumber`. Renderer всегда отмечает его знаком
`≈`:

```text
≈1.4142135623730950488
```

Это позволяет отличить

```text
1.4142135623730950488
```

как точный рациональный литерал от результата численного вычисления.

`ApproxNumber` имеет статический тип `Real`, сохраняется в IR версии 7 и может
храниться в окружении:

```text
a = sqrt(2) |> numeric(40)
print(a)
```

При этом точные `simplify` и `normalize` не начинают выполнять скрытую
плавающую арифметику над такими значениями. Численное вычисление остаётся
явным действием.

## Точность

Ядро не использует `float`. Вычисление построено на стандартном
`decimal.Decimal` с защитными дополнительными разрядами.

- `sqrt`, `exp` и `log` используют высокоточную Decimal-арифметику;
- `sin` и `cos` вычисляются степенными рядами после сведения аргумента;
- π для сведения аргумента вычисляется алгоритмом Гаусса—Лежандра;
- `tan(x)` вычисляется как `sin(x)/cos(x)`.

Параметр `digits` задаёт количество **выводимых значащих цифр**, а внутренний
контекст использует дополнительные guard digits для округления.

Текущая версия не хранит строгую математическую оценку погрешности как часть
IR. Поэтому `≈` означает численное приближение с заданной рабочей точностью,
но не interval/ball certificate.

## Ошибки и ограничения

`numeric` намеренно отказывается вычислять выражение, если оно не стало
замкнутым вещественным числом.

```text
variable x : Real
x |> numeric
// ошибка: unresolved symbol 'x' remains
```

Также диагностируются:

- деление на ноль;
- `log(x)` при `x <= 0`;
- `sqrt(x)` при `x < 0`;
- дробная степень отрицательного вещественного основания;
- неподдерживаемый вызов пользовательской функции, который не был раскрыт;
- элементы пользовательской алгебры;
- комплексные значения;
- недопустимая точность.

Комплексный численный backend и численное вычисление координат элементов
алгебр — отдельные будущие расширения. Символьный `analytic_lift` для алгебр
остаётся точным и не зависит от `numeric`.

## Python API

Низкоуровневый API также доступен:

```python
from mathlang import Session, evaluate_numeric, format_term

s = Session()
term = s.resolve("sqrt(2)")
value = evaluate_numeric(s.factory, term, s.factory.number(50), limits=s.kernel.limits)
print(format_term(value))
```

Для обычного использования предпочтителен синтаксис самого языка:

```text
sqrt(2) |> numeric(50)
```
