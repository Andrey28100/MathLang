# Конечные итерации — 0.8.1–0.8.2

## Операции

| Вызов | Результат |
| --- | --- |
| `iterate(f, initial, count)` | `count` повторений `state = f(state)` или `f(state,index)`, начиная с initial |
| `sum(f, lower, upper)` | Сумма `f(k)` по целым k от lower до upper включительно |
| `product(f, lower, upper)` | Произведение `f(k)` в том же порядке |
| `all(f, lower, upper)` | Конъюнкция предикатов `f(k)` |
| `any(f, lower, upper)` | Дизъюнкция предикатов `f(k)` |

Для свёрток `f` — функция одного аргумента: имя, lambda, замыкание или совместимая
символическая функция. `iterate` также принимает функцию двух аргументов:
состояния и индекса шага. Границы — целые числа, count — неотрицательное целое.
Отрицательные индексы допускаются; шаг диапазона равен +1. Цепочки вложенных
вызовов и захват внешних параметров работают через обычные функции языка.

```text
iterate(x=>2*x+1, 1, 4)                 // 31
iterate(x=>x/2, 1, 3)                   // 1/8
sum((k:Integer)=>k^2, -2, 2)            // 10
product(k=>k, 1, 5)                     // 120
sum(k=>sum(j=>j*k, 1, 3), 1, 2)         // 18
```

## Блок и тип индекса

Начиная с 0.8.2 функцию можно записать после аргументов в фигурных скобках:

```text
iterate(1, 6) {
    (value:Nat, index:Nat) => value*index
}                                       // 720

sum(-2, 2) {
    (index:Integer) => index^2
}                                       // 10

product(1, 6) {(index:Nat) => index}      // 720
```

У `iterate(1,n)` число 1 — **начальное состояние**, n — **число шагов**.
Индекс имеет тип `Nat` и принимает значения 1, 2, …, n. Начальному состоянию
соответствует шаг 0; тело на шаге 0 не вызывается. У sum/product/all/any два
аргумента по-прежнему задают включённые границы диапазона, а не состояние.

Блок содержит одно lambda-выражение с явно названными параметрами. Аннотации
типов необязательны: `iterate(1,3) {(s,i)=>s+i}` даёт 7. В блоке пока нельзя
писать инструкции или `return`; сложный шаг можно определить отдельной
`function` с локальными определениями. Сохраняется и вариант с одним
параметром: `iterate(1,3) {s=>2*s}`.

Это сокращение обычного вызова: `iterate(a,n) {f}` с lambda f превращается
в `iterate(f,a,n)`. Поэтому обе записи имеют одинаковые области видимости,
проверку типов, Typed IR, лимиты и сохранение. Аннотация `index:Predicate`
отклоняется; `index:Integer` принимает натуральный индекс через безопасное
вложение. Индекс свёртки допускает `Nat`, когда нижняя граница неотрицательна,
и требует `Integer` при возможных отрицательных значениях.

## Выражение с символом связывания

Есть форма с выражением и заранее объявленным символом:

```text
k:Integer
x:Real
sum(k^2, k, 1, 10)                      // 385
product(k+1, k, 0, 3)                   // 24
iterate(x^2, x, 2, 3)                   // 256
```

Второй аргумент связывается только внутри первого выражения. Начальное значение
и границы остаются во внешней области, а объявленный символ не заменяется
последним индексом/состоянием. Число или именованное выражение вместо символа
связывания отклоняется. Lambda-форма не требует предварительного объявления.

## Семантика вычисления

`iterate(f,a,0)` возвращает исходный терм a без вычисления тела f и без
автоматического упрощения a. Если upper < lower, диапазон пуст; результаты:
0 для sum, 1 для product, True для all и False для any. Тело f не вычисляется.
Проверка типов и сигнатур выполняется и для нулевого числа шагов.

Каждый выполненный шаг iterate и арифметической свёртки упрощает результат
существующим скалярным/алгебраическим ядром с текущими предположениями.
Значения остаются точными: `0.1` — рациональное 1/10. Порядок множителей
сохраняется даже для некоммутативных алгебр. Поддерживаются скаляры, значения
имеющихся алгебр и состояния-функции с упрощаемым телом; конструкторы матриц
и векторов этим дополнением не вводятся.

У функции iterate должен быть стабильный тип состояния. Без аннотации
разрешается безопасное расширение, например Nat → Rational для `x=>x/2`.
Явная аннотация состояния сохраняется и у функции двух аргументов.
У аннотированной `(x:Nat)=>x-1` результат выходит из Nat — такой шаг
отклоняется. Нельзя незаметно изменить форму состояния со скаляра на функцию.
Для all/any функция должна возвращать Predicate; для sum/product — скаляр
или значение алгебры. Индекс получает Nat, если нижняя граница заведомо
неотрицательна, иначе Integer.

all останавливается на False, any — на True. Unknown не становится истиной;
если решающего ответа нет и хотя бы один ответ неизвестен, результат Unknown.
Последующие индексы после остановки не вычисляются. Это свойство относится
к свёртке, а не к обычным операторам and/or внутри её тела.

## Символические границы

```text
n:Nat
S=sum(k=>k^2, 1, n)
S                                      // символическая сумма, в IDE знак ∑
substitute(S, n=10)                     // 385
```

Если тип границы подходит, но её точное значение неизвестно, вызов сохраняется
в виде FunctionCall и вычисляется после подстановки. Аналогично работает iterate
с символическим count. Предикатная свёртка с неизвестной границей при запросе
даёт Unknown. Общие формулы вроде `n*(n+1)/2` автоматически не выводятся.
Для символической конечной суммы доступны почленные `derivative`,
`antiderivative`, `integrate` и `limit`, если границы не зависят от координаты
анализа. Контракт и примеры: [CALCULUS.md](CALCULUS.md).
Не все выражения с нераскрытыми свёртками поддерживаются скалярным simplifier;
подставьте границы перед дальнейшей арифметической нормализацией.

Синтаксис использует существующие Function и FunctionCall IR, включая связывание
символов, подстановки и Typed IR. Функции с итерациями и символические свёртки
сохраняются в формате mathlang-ir 6. Старый читатель, не знающий новых встроенных
имён, отклонит такие объекты. Python API: `Session.resolve/execute/typed_ir`.

## Встроенный факториал

`factorial(n)` имеет сигнатуру `Function<Nat,Nat>`, вычисляется точно и
удовлетворяет `factorial(0)=1`. Отрицательные, дробные значения и неверное
число аргументов отклоняются. Символический аргумент `n:Nat` сохраняется
до подстановки. В математическом preview показывается n!; исходная запись
остаётся `factorial(n)`, постфиксный оператор `!` пока не вводится.

```text
factorial(6)                             // 720
n:Nat
F=factorial(n)
substitute(F,n=5)                       // 120
```

Вычисление использует тот же общий бюджет итераций и ограничение размера чисел,
что и свёртки; вложенный factorial не сбрасывает счётчики. Пример сравнения
факториала, product и блочной итерации: [series_calculus.math](../examples/series_calculus.math).

## Ограничения и ошибки

По умолчанию `Limits.max_iterations = 10000`. Бюджет общий для вложенных
итераций одного вызова ядра. Диапазон, уже превышающий оставшийся бюджет,
отклоняется до обхода, в том числе для all/any. Дополнительно действуют
`max_steps`, `max_nodes` и `max_integer_bits`.

Ошибки тела, деление на ноль и исчерпание бюджета не превращаются в Unknown
или частичный численный ответ. Неудачный ввод откатывается целиком.
Бесконечные суммы, произвольный шаг и множество индексов, потоки, общий fold
и численные backend'ы для массового расчёта пока не добавлены.

## Пример Мандельброта

[examples/mandelbrot.math](../examples/mandelbrot.math) определяет
`mandelbrot(cr,ci,steps)` для комплексной точки c = cr + ci·i.
Орбита начинается с z₀=0 и повторяет zₙ₊₁=zₙ²+c. Выход при |zₙ|>2
доказывает непринадлежность; конечное отсутствие выхода само по себе не
доказывает принадлежность. Используются также достаточные условия для
главной кардиоиды и компоненты периода 2. Формулы сверены с
[материалом Jan Macharáček, Masaryk University](https://www.math.muni.cz/~xmacharacekj/renderingAlgorithmsMandelbrot.html)
и [учебным разбором Jean-Christophe Loiseau](https://loiseaujc.github.io/Scientific_Computing_on_a_Laptop/Maths/Mandelbrot/binary_mandelbrot.html).

Пара координат представлена функцией point: `p(0)` возвращает вещественную
часть, `p(1)` — мнимую. Это демонстрация уже существующих функций первого
класса; формула шага записана как `(x²−y²+cr, 2xy+ci)` средствами языка.
Никакой специальной ветки для Мандельброта в Python-ядре нет.
norm_squared использует sum, а последний пример product вычисляет произведение
квадратов радиусов нескольких точек орбиты.

| Вызов | Ответ | Причина |
| --- | --- | --- |
| `mandelbrot(0,0,4)` | True | Достаточное аналитическое условие |
| `mandelbrot(-1,0,4)` | True | Компонента периода 2 |
| `mandelbrot(1,0,2)` | Unknown | Первые значения 1 и 2 ещё не выходят за радиус |
| `mandelbrot(1,0,3)` | False | Третье значение 5 |
| `mandelbrot(1,1,4)` | False | Обнаружен выход |
| `mandelbrot(-2,0,4)` | Unknown | Радиус ровно 2; пример не доказывает эту принадлежность |
| `mandelbrot(-3/4,1/10,3)` | Unknown | Заданных шагов недостаточно для решения |

Пример проверяет отдельные точки точной арифметикой. bounded_through намеренно
составлен из all и iterate и заново вычисляет орбиту для каждого индекса:
при отсутствии выхода требуется N(N+1)/2 шагов iterate и N шагов all.
Обычный or также не пропускает расчёт второй стороны после аналитического True.
Поэтому большой бюджет итерирования может исчерпать лимиты даже для точки внутри
множества; рациональные числители и знаменатели быстро растут. Это учебный
проверяющий пример, а не быстрый растровый генератор фрактала.

Проверки в `tests/test_iteration.py` сравнивают координаты с независимым
расчётом Fraction, проверяют пустые диапазоны, связывание, вложенные бюджеты,
неопределённость, порядок произведений, Typed IR, CLI, сохранение и MathText.
