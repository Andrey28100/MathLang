# Логика и предположения — контракт 0.8.0

Реализация разделов 39–41 спецификации 0.1 для ограниченного фрагмента.
Это слой символьных предикатов и запросов в контексте. Контракты теорий,
аксиомы-обязательства и forall добавлены в [0.9.0](THEORIES.md);
общие сертификаты условных доказательств относятся к последующим этапам.

## Синтаксис и значения

`Predicate` — отдельный математический тип без параметров. Узлы `Comparison`,
`Logical`, `Defined` и `Truth` наследуют `Predicate` и входят в неизменяемый
`Term` DAG. Elaborator строит для них отдельный Typed IR.

| Запись | Значение |
| --- | --- |
| `a == b`, `a != b` | Математическое равенство и его отрицание |
| `a === b` | Совпадение структуры и идентичностей символов, без преобразований |
| `a < b`, `a <= b`, `a > b`, `a >= b` | Порядок над вещественными скалярами |
| `p and q`, `p or q`, `not p` | Трёхзначные логические операции |
| `query(p)` | Текущее значение `True`, `False` или `Unknown` |
| `domain(e)` | Предикат определённости выражения `e` |
| `assume p` | Добавление условия в текущую область видимости |
| `assuming {p; q} { ... }` | Локальные условия и локальные определения |

Арифметика связывает сильнее сравнений, далее идут `not`, `and`, `or`.
Поэтому `not x>0 and y!=0` означает `(not (x>0)) and (y!=0)`.
Цепочки `0<x<1` отклоняются; пишите `0<x and x<1`. При сравнении результата
pipeline используйте скобки: `(x+x |> simplify) == 2*x`.

В контексте условия `=` является синонимом `==`: `assume x=0`.
Обычный оператор `x=0` по-прежнему задаёт именованное выражение.
На правой стороне определения используйте `p=x==0` или `p=(x=0)`.
В вызове `query(x=0)` синтаксис означает именованный аргумент и отклоняется;
правильные формы — `query(x==0)` и `query((x=0))`. Синтаксис отношений алгебр
и `prove left = right` сохраняется.

Сравнения скаляров используют существующую башню типов и явные `Embed` в Typed IR.
Математическое равенство требует совместимых типов; порядок не определён над
`Complex`, матрицами, предикатами или номинальными алгебрами. `===` допускает
разные типы и не вставляет вложений. Логические операции требуют `Predicate`;
`1 and True` — ошибка типа. Неизвестные типы параметров функций могут оставаться
отложенными до вызова, как в 0.7.

## Трёхзначная логика

`Unknown` означает отсутствие установленного ответа. В частности, разные
символьные нормальные формы сами по себе не доказывают неравенство.

| p | q | p and q | p or q |
| --- | --- | --- | --- |
| True | True | True | True |
| True | False | False | True |
| True | Unknown | Unknown | True |
| False | True | False | True |
| False | False | False | False |
| False | Unknown | False | Unknown |
| Unknown | True | Unknown | True |
| Unknown | False | False | Unknown |
| Unknown | Unknown | Unknown | Unknown |

`not True = False`, `not False = True`, `not Unknown = Unknown`.
Для математического сравнения `Unknown==Unknown` ответ `Unknown`, а для
структурного `Unknown===Unknown` — `True`. Вычисление логических операндов
не обещает программного короткого замыкания: явные преобразования внутри
аргументов могут сообщить ошибку до логического запроса.

Предикаты хранятся символически и запрашиваются при выводе:

```text
parameter x:Real
p = x>0
snapshot = query(p)
p                              // Unknown
assume x>0
p                              // True
snapshot                       // Unknown
```

`query` фиксирует ответ на момент вызова. `simplify(p)` и `normalize(p)` также
возвращают значение истинности. Функция может возвращать `Predicate`:
`function positive(t:Real):Predicate {return t>0}`.
Подстановка и явное переписывание обходят операнды предикатов.

## Контекст и области видимости

`Context` содержит неизменяемый `AssumptionSet`. Дочерние окружения наследуют
его текущий снимок; новые условия не изменяют родительский контекст.
В `assuming` условия разделяются переносами строк, `;` или запятыми.
Вложенные блоки наследуют внешние условия и теряют собственные после выхода:

```text
parameter x:Real
assuming {x>=0} {
    simplify(sqrt(x^2))         // x
    assuming {x>2} {x>1}        // True
    x>1                        // Unknown
}
x>=0                           // Unknown
```

В REPL верхнеуровневый `assume` действует до конца сессии. При ошибке весь
текущий ввод откатывается вместе с определениями, условиями и импортами.
`False`, чистое значение `Unknown`, известное противоречие и заведомо
неопределённый предикат нельзя принять как предположение. Уже установленное
истинное условие повторно не добавляется. Конъюнкция проверяется по частям;
из принятой дизъюнкции не выбирается произвольная ветвь.

Проверка согласованности ограничена поддерживаемыми методами вывода. Она
не является общим решателем выполнимости: сложное противоречие может оставаться
нераспознанным. Известные конфликты, включая позднее нарушение области
определения старого условия, отклоняются независимо от порядка ввода.

Тип задаётся объявлением `n:Integer`; форма `assume n:Integer` пока отсутствует.
Тело функции по-прежнему состоит из локальных определений и завершающего
`return`: операторы `assume`/`assuming` внутри него пока не допускаются.
При вызове функции явные преобразования используют текущий контекст вызывающей
области; отдельного контракта предусловий функции ещё нет.

## Поддерживаемый вывод и упрощение

- Точные рациональные сравнения и арифметические константы.
- Структурная идентичность и математическое равенство нормальных форм скалярного
  либо зарегистрированного алгебраического нормализатора.
- Принятые условия, их конъюнкции, отрицания и обращения сторон сравнения.
- Границы одной и той же величины: `x>2` даёт `x>=0`, `x!=0` и опровергает `x<=2`.
- Неотрицательность `Nat` и положительных чётных степеней вещественного основания.
- Условия определённости основных скалярных операций.

При установленном `x>=0` упрощаются `sqrt(x^2)` и `abs(x)` до `x`;
при `x<=0` — до `-x`. Установленная определённость разрешает сокращение
`x/x`, `0/x`, `x^0`, если `x!=0`. Без условия частичные выражения сохраняются.

Существующая форма `rule r {sqrt(t^2) -> t when t>=0}` использует тот же
контекст запросов. Только ответ `True` разрешает применение; `Unknown` и
`False` не разрешают. `when` пока допускает одно сравнение арифметических
шаблонов; составные условия и логические шаблоны не добавлены.
Пользовательские правила остаются преобразованиями, а не аксиомами доказательств.

Нет общего решателя уравнений/неравенств, транзитивного вывода произвольных
отношений, подстановки всех принятых равенств или доказательства по случаям.
Алгоритмы derivative/antiderivative/series/limit пока не используют assumptions
для выбора формул и ветвей; это отдельная будущая часть анализа.

## Область определения

`domain(e)` возвращает предикат, а не множество значений переменных.
При его запросе `True` означает установленную определённость, `False` —
установленную неопределённость, `Unknown` — недостаток условий.

| Выражение | Условие сверх определённости аргументов |
| --- | --- |
| `a+b`, `a-b`, `a*b` | Нет дополнительного условия |
| `a/b` | `b!=0` |
| `a^n`, положительное целое n | Нет дополнительного условия |
| `a^n`, неположительное целое n | `a!=0`, включая принятую границу `0^0` |
| Общая степень | Положительность основания достаточна; остальные случаи могут быть Unknown |
| `sin(a)`, `cos(a)`, `exp(a)`, `abs(a)` | Нет дополнительного условия |
| `sqrt(a)` над Real | `a>=0` |
| `log(a)` над Real | `a>0` |
| `sqrt(a)`, `log(a)` над Complex | Для sqrt нет дополнительного условия, для log требуется `a!=0` |
| `tan(a)` | `cos(a)!=0` |

Например, `domain(1/0)` и `domain(sqrt(-1))` дают `False`;
`domain(1/x)` без условий даёт `Unknown`. После `assume domain(log(x))`
установлено `x>0`, поэтому `assume x<=0` отклоняется.
Комплексные условия не являются реализацией общего анализа ветвей.
Внешняя символическая функция без доступного тела имеет неизвестную область.

Математическое сравнение частичных выражений требует их определённости:
`1/x==1/x` без условий даёт `Unknown`, а после `assume x!=0` — `True`.
Структурное `1/0===1/0` даёт `True`: оно сравнивает термы.

## Python API, REPL и переносимость

```python
from mathlang import Context, PredicateQuery, Session, TruthValue

s = Session()
s.execute('x:Real')
p = s.resolve('x>0')
assert s.query(p) is TruthValue.UNKNOWN
assert s.query(s.domain('1/x')) is TruthValue.UNKNOWN
s.execute('assume x>0')
assert s.query(p) is TruthValue.TRUE

# Независимый контекст; исходная сессия не меняется.
engine = PredicateQuery(s.factory, context=Context())
local = engine.assuming(p)
assert PredicateQuery(s.factory, context=local).query(p) is TruthValue.TRUE
```

Для алгебраических предикатов предпочтителен `Session.query`: он передаёт
реестр алгебр и лимиты ядра. При низкоуровневом использовании передавайте
`algebras` и `limits` явно. Стройте проверяемые контексты через `.assuming()`;
прямой конструктор `Context(AssumptionSet(...))` является контейнером доверенных
данных и не запускает проверку согласованности.

`bool(TruthValue.UNKNOWN)` и `bool(symbolic_predicate)` вызывают `TypeError`.
Проверяйте результат через `is TruthValue.TRUE`. Запросы ограничены бюджетами
шагов, нормализации и числа условий; исчерпание бюджета сообщает ошибку.

REPL предоставляет `:assumptions` и `:query x>0`. IDE показывает текущие условия
в панели **Assumptions**, а диагностику буфера выполняет в отдельной сессии.

Предикаты, символы и значения истинности сохраняются начиная с `mathlang-ir` 3;
текущий формат 7 читает версии 1–6. `Context` не сериализуется. Экспорт модуля с
активными assumptions отклоняется; namespace также не может экспортировать
свои локальные предположения. Для локальной работы используйте `assuming`.

Действующий `prove` отклоняется при непустом контексте: его сертификат пока
не содержит assumptions. Ответ `query` не является переносимым сертификатом.
Общий proof object с явными зависимостями остаётся этапом 0.10.

Запускаемый пример: [examples/logic.math](../examples/logic.math).
Проверки: `tests/test_logic.py`, `tests/test_ide_service.py`, `tests/test_ide_editor.py`.
